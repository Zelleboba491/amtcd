# AmTCD — блокнот с прозрачным шифрованием

Текстовый редактор на Python и tkinter. Файлы на диске хранятся в зашифрованном виде, а в окне пользователь работает с обычным текстом. Учебный проект по криптографии.


## Возможности

- Шифрование при сохранении и расшифровка при открытии, файлы с расширением `.txtx`.
- Двухуровневый ключ: личный и сессионный, который меняется при каждом сохранении. Один и тот же текст каждый раз шифруется по-разному.
- Проверка ключа при открытии: при неверном ключе или повреждённом файле появляется сообщение об ошибке, а не бессмысленный текст.
- Окно «Параметры» проверяет ключ на простоту прямо при вводе, генерирует случайный простой ключ и копирует его в буфер обмена.
- Предупреждение о несохранённых изменениях, звёздочка в заголовке, строка состояния с текущим ключом.
- Тёмная тема, горячие клавиши, переход между кнопками по Tab.

## Запуск

Нужен Python 3.8 или новее, только стандартная библиотека.

```bash
python amtcd.py
```

При первом запуске задайте личный ключ: «Правка → Параметры» или кнопка «🔑 Ключ». Ключ сохраняется в `AmTCD.ini` в папке, из которой запущена программа. Иконка `AmTCD.ico` необязательна.

## Как устроено

### Шифрование

1. Личный ключ `p` — простое число от 2 до 10 000 000.
2. При каждом сохранении выбирается случайное простое число `s` — сессионный ключ.
3. Младшие 32 бита произведения `p × s` становятся начальным состоянием линейного конгруэнтного генератора: `x(n+1) = (1664525 · x(n) + 1013904223) mod 2³²`.
4. Код каждого символа текста складывается по XOR с числом гаммы `(x(n) mod 127) + 1`.
5. Контрольная сумма — полиномиальный хеш шифртекста (основание 31, модуль 10²⁶) с начальным значением `p × s`. При открытии она пересчитывается с текущим ключом и сравнивается с записанной в файле.

### Формат файла `.txtx`

Обычный INI-файл. Пример для текста «Привет»:

```ini
[main]
keyopen = 00000000736050279479433170
session = 104729
mess = 50043404340453042e046604
```

| Поле | Содержимое |
| --- | --- |
| `keyopen` | контрольная сумма, 26 цифр |
| `session` | сессионный ключ `s` |
| `mess` | шифртекст в кодировке UTF-16-LE, записанный в hex |

### Структура кода

| Блок | Что делает |
| --- | --- |
| `is_prime`, `rand_prime` | проверка на простоту и генерация случайного простого числа |
| `xor_crypt`, `fingerprint` | шифрование и контрольная сумма |
| `file_save`, `file_load`, `cfg_load`, `cfg_save` | чтение и запись `.txtx` и `AmTCD.ini` |
| `KeyDialog` | окно «Параметры» |
| `App` | главное окно: меню, панель кнопок, редактор, строка состояния |

## Ограничения безопасности

Это учебная реализация, настоящие секреты ей доверять нельзя:

- Личных ключей всего 664 579 — столько простых чисел до 10 000 000. Сессионный ключ записан в файле открыто, а контрольная сумма позволяет проверить догадку. Поэтому личный ключ подбирается перебором.
- Состояние генератора — 32 бита, и последовательность ЛКГ предсказуема.
- XOR меняет только младшие 7 бит кода символа. По шифртексту видно, к какому алфавиту относился каждый символ: кириллица остаётся кириллицей, латиница — латиницей.
- Личный ключ хранится в `AmTCD.ini` открытым текстом.
- Случайные числа берутся из модуля `random`, который не предназначен для криптографии.

В рабочей программе стоит использовать AES-GCM из библиотеки `cryptography`, получать ключ из пароля через scrypt или PBKDF2, а случайные значения брать из модуля `secrets`.
